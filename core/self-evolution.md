# Self-Evolution Engine

> **AgentSeed 核心创新**：宪法教会 Agent "什么时候该自己找资源"，而不只是"不能做什么"。

## 设计哲学

AgentSeed 不是一个静态预设注入器。它赋予 Agent **自主检测能力缺口 → 评估解决方案 → 执行获取动作 → 验证并热加载** 的完整能力链。

当用户提出一个需要特定工具/知识的请求，而当前 Persona Pack 未覆盖该领域时，Agent 不应该简单回复"我做不到"——它应该自主判断：**这个缺口能不能通过搜索/克隆/安装来补上？**

## Capability Gap Score (能力缺口评分)

当 Agent 无法用现有资源满足用户请求时，计算缺口分数：

```
GapScore = Σ( w_i × factor_i )

因子                       权重   说明
────────────────────────────────────────────────
MissingToolScore           0.35   需要的工具不存在
MissingKnowledgeScore      0.25   领域知识缺失
UserIntentUrgency          0.20   用户显式要求=1.0 / 隐式=0.5
AlternativeExhaustedScore  0.10   已有替代已失效=1.0 / 未尝试=0
RiskOfActionScore          0.10   低=1.0 / 中=0.5 / 高=0（越安全越能触发）
```

**MissingToolScore 计算**：
- 用户所需工具不在 Skills/MCP 列表中 → 1.0
- 存在但功能不完整 → 0.6
- 存在但不匹配用户问题领域 → 0.3
- 完全具备 → 0

**MissingKnowledgeScore 计算**：
- 请求领域完全不在 Persona Pack 覆盖范围 → 1.0
- 有相关 Capability 但内容不足以回答 → 0.6
- 可回答但高质量相关源可增强结果 → 0.3
- 知识完全覆盖 → 0

### 阈值决策

```
GapScore < 0.30   → 不做任何事，用现有能力尽力回答
GapScore 0.30-0.55  → 输出建议命令供用户手动执行
GapScore 0.55-0.75  → 执行低风险获取（搜索/clone 只读仓库/下载公开包）
                      但需告知用户
GapScore > 0.75   → 全自动获取 + 配置 + 热加载，完成后告知
                      （P0 例外：MCP 不自安装、密钥不自配）
```

## Action Decision Matrix

| 缺口类型 | GapScore 范围 | 动作 | 工具 | 约束 |
|---------|-------------|------|------|------|
| 缺少领域知识 | 0.30-0.75 | web_search | DAR T1-T4 打分 | ≤3 次搜索 |
| 缺少领域知识 | >0.75 | search→fetch→整合 | DAR + 多源验证 | 标注来源 |
| 缺少技能/模板 | 0.30-0.75 | 推荐命令 | 输出供用户执行 | 不自动克隆 |
| 缺少技能/模板 | >0.75 | git clone / pip install | 自动 | 排除.git |
| 缺少 MCP 工具 | 任意 | 输出配置 JSON | 仅输出 | **P0: 绝不自动安装** |
| 环境依赖 | 0.55-0.75 | 推荐安装命令 | 输出 | 不自动 sudo |
| 环境依赖 | >0.75 | 自动安装 | pip/npm/brew | 先检查是否已存在 |
| 现有效能不足 | >0.55 | 自我评估→替换 | 卸载旧→安装新 | 备份配置 |

## Quality Gate (三关验证)

自动获取的任何内容，必须通过：

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│ Gate 1: 安全  │ →   │ Gate 2: 质量  │ →   │ Gate 3: 兼容  │
│              │     │              │     │              │
│ • 无恶意代码  │     │ • 测试通过    │     │ • 无规则冲突  │
│ • .git 已清   │     │ • lint 通过   │     │ • 画像兼容    │
│ • 密钥无泄露  │     │ • 文档完整    │     │ • 版本兼容    │
└──────────────┘     └──────────────┘     └──────────────┘
  ❌ → 拒绝+报告       ❌ → 降级告知用户     ❌ → 隔离+建议
```

## Confidence-Weighted Action Model

```
置信度 = 基础先验 × (匹配信号 / 信号噪声)

基础先验：
  T1 来源（官方文档/论文）命中 → 0.85
  搜索命中 ≥3 个 T1/T2 源 → 0.70
  搜索命中 1-2 个 → 0.50
  无有效搜索结果 → 0.20

信号调节：
  内容语义相关度（0-1）
  来源一致性（多源一致 +0.1/源，矛盾 -0.15/源）
  时效性（<6月 +0.1，>2年 -0.1）

最终：
  置信度 ≥ 0.80 → 采纳并整合
  0.50 ≤ 置信度 < 0.80 → 采纳但标记"待验证"
  置信度 < 0.50 → 仅输出建议
```

## 触发时序

```
用户请求
  │
  ▼
Persona Pack + Skills + MCP 能否满足？
  │
  ├─ 能 → 正常执行
  │
  └─ 不能 → 计算 GapScore
              │
              ├─ < 0.30 → 尽力回答，告知局限
              ├─ 0.30-0.55 → 输出建议命令
              └─ > 0.55 → 执行获取动作
                            ├─ web_search（知识缺口）
                            ├─ git clone（技能缺口）
                            └─ pip/npm install（依赖缺口）
                              │
                              ▼
                          Quality Gate（三关）
                              │
                              ├─ 通过 → 热加载到会话
                              └─ 失败 → 降级告知用户
```

## 与现有系统的关系

- **governance.md** 定义 P0 红线（如 MCP 不自安装）——Evolution Engine 必须遵守
- **dar-spec.md** 定义搜索权威打分 ——Evolution Engine 搜索阶段使用
- **persona-router.md** 定义画像路由 —— Evolution Engine 获新包时触发重路由
- **constraints.yaml** 定义机器可执行约束 —— Evolution Engine Quality Gate 使用
