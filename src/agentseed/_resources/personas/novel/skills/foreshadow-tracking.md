# Foreshadow Tracking（伏笔追踪系统）

> AI 写长篇容易"埋了不收"或"硬收无铺垫"——前者让读者感觉被欺骗，后者让读者感觉突兀。本文件强制用台账追踪每一条伏笔的埋设与回收。
> 与 `truth-protocol.md` §8 Confidence Calibration 联动——伏笔未回收即"叙事承诺未兑现"，直接拉低叙事完整度置信度。

## §1 核心理念 / Core Principle

伏笔是作者对读者的隐性承诺。每埋一条伏笔，就在读者心里建立一份期待；这份期待不被兑现，读者会感到被欺骗。

伏笔追踪三原则：
- **每埋必记**：埋设伏笔时立即入台账，记录位置与预期回收点。
- **每收必查**：回收伏笔时核对台账，确认铺垫充分、回收自然。
- **未收必处**：交稿前对未回收伏笔逐条处置——补写回收或显式废弃。

## §2 伏笔台账模板 / Foreshadow Ledger

每条伏笔一个台账条目，写作过程中持续维护。

```markdown
| 伏笔ID | 埋设章节位置 | 内容 | 预期回收点 | 实际回收位置 | 回收质量 | 状态 |
|--------|------------|------|----------|------------|---------|------|
| F-001  | 第2章·酒馆  | 老人低语"黑潮将至" | 第15章高潮 | 第14章末 | L4 | 已回收 |
| F-002  | 第3章·密室  | 墙上无字符号       | 第10章揭秘 | —        | —   | 未回收 |
| F-003  | 第5章·对话  | 主角失忆前的暗示   | 第18章揭秘 | 第12章   | L2 | 已回收(待修订) |
| F-004  | 第6章·场景  | 角落红披风路人     | 未规划     | —        | —   | 已废弃 |
```

字段说明：
- **回收质量**：使用 §4 四级评估（L4/L3/L2/L1），未回收留空。
- **状态**：未回收 / 已回收 / 已废弃（废弃需在文中淡化残留线索，见 §5）。

## §3 Foreshadow_Resolution_Rate 公式 / Resolution Rate

```
Foreshadow_Resolution_Rate = 已回收伏笔数 / 已埋设伏笔数

注：已废弃伏笔从分母中扣除（即不计入"应回收"基数）。
```

| Resolution_Rate | 评级 | 处置要求 |
|----------------|------|---------|
| ≥ 0.9 | 优秀 | 可交稿 |
| 0.7 – 0.9 | 合格 | 检查低质量回收项，建议优化 |
| < 0.7 | 不合格 | **必须补回收或显式废弃**，禁止直接交稿 |

## §4 回收质量四级评估 / Payoff Quality

对每条已回收伏笔评估回收质量：

| 等级 | 名称 | 标准 | 处置 |
|------|------|------|------|
| L4 | 完美 | 铺垫充分、回收自然、有惊喜感（读者"原来如此"） | 保留 |
| L3 | 良好 | 铺垫充分、回收合理（读者"说得通"） | 保留 |
| L2 | 及格 | 有铺垫但回收生硬（读者"有点牵强"） | **必须修订** |
| L1 | 不及格 | 无铺垫硬回收，或回收与前文矛盾（读者"硬凑/穿帮"） | **必须修订** |

**强制规则**：回收质量 ≤ L2 的伏笔必须修订——要么补铺垫使其升到 L3+，要么改写回收方式，要么显式废弃。

## §5 处置流程 / Disposal Workflow

```
1. 扫描全稿 → 识别所有伏笔埋设点，建立台账（§2 模板）
2. 逐条标状态 → 已回收 / 未回收 / 已废弃
3. 计算 Resolution_Rate → 对照 §3 阈值表判断是否合格
4. 处置未回收伏笔 →
     - 优先：补写回收章节（保持铺垫-回收链条完整）
     - 次选：显式废弃——在文中淡化残留线索（删减提及、降级为背景细节），
            避免读者察觉"挖坑不填"
5. 修订低质量回收 → 对 ≤ L2 的回收项，按 §4 升级到 L3+ 或改写
```

废弃伏笔的淡化标准：读者重读时不应再将其识别为"伏笔"，最多视为闲笔。

## §6 失败信号 / Failure Signals

| 信号 | 描述 | 危害 |
|------|------|------|
| 未建台账就交稿 | 全凭记忆追踪伏笔 | 长篇必然遗漏，读者挖坑党会逐条对照 |
| 未回收伏笔保留 | 已埋未收且未废弃 | "承诺未兑现"，读者信任崩塌 |
| 硬回收无铺垫 | L1 等级回收留稿 | 读者出戏，感觉作者强行圆满 |
| 废弃伏笔残留明显线索 | 已废弃但文中提及过强 | 读者继续期待，反而强化"挖坑不填"印象 |

任一信号出现，视为本 skill 未正确执行，必须回到 §5 流程补全。

## §7 与其他文档的关系 / Relationships

- **`context-management.md`**：伏笔台账是长期记忆的一部分，应持久化到 `.ai-memory/plot-threads.md`，避免跨会话遗忘。
- **`plot-architecture.md`**：伏笔服务于主线与支线结构，台账与情节架构互校——主线伏笔必须回收，闲笔可废弃。
- **`truth-protocol.md` §8 Confidence Calibration**：Foreshadow_Resolution_Rate 作为"叙事完整度置信度"输入；Rate < 0.7 时叙事置信度强制降到"低"。
- **`revision-strategy.md`**：修订阶段（尤其第一层结构修订）必查伏笔台账，优先处理未回收与低质量回收项。
